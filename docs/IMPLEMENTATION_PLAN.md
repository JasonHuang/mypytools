# Toolmist 公共工具站实施计划

## 1. 计划目标

在不改变现有生产入口的前提下，把当前单文件 Flask 图片 GUI 重构为可扩展的公开工具站，并完成首期三个工具：

1. 图片压缩。
2. 图片格式转换。
3. 浏览器本地文件名提取。

整个过程在分支 `feat/toolmist-public-toolbox` 上进行。生产仍使用：

- 域名 `toolmist.com`。
- Caddy 反向代理 `127.0.0.1:5001`。
- Compose 项目名 `toolmist`。
- Docker 健康检查 `/healthz`。

## 2. 实施策略

### 2.1 小步迁移

重构拆成能够独立测试和回滚的提交，不采用一次性替换全部代码的方式。

### 2.2 先边界，后页面

先建立应用结构、临时文件模型、统一错误和输入限制，再让新页面使用新 API。这样页面上线时不会依赖旧的不安全路径模型。

### 2.3 保持生产兼容

- 容器端口保持 `5001`。
- `/healthz` 保持公开和快速响应。
- Compose 服务名保持 `image-tools`，首轮不要求修改 Caddy。
- 旧 API 在新页面切换完成前可以短暂保留，之后统一删除。

## Phase 2：任务制临时文件与 API v1

2. 使用不可枚举的任务 ID 和服务端元数据。

4. 新建图片压缩 API v1。

7. 增加任务失败即时清理。
8. 增加 TTL 清理命令，并在容器中周期执行。
9. 删除公开日志 API。

验收：

- 客户端无法指定任何服务器路径。
- 两个任务的文件目录完全隔离。

- 超像素、超文件数、超请求大小返回稳定错误码。
- 过期下载返回 `404` 或 `410`。
- 日志不包含绝对路径和完整原始文件名。

## Phase 4：三个首期工具接入

状态：实现完成；待浏览器交互验收。

目标：完成首期真实工作流。

### 4.1 图片压缩

- 使用 API v1。
- 明确输出始终为 JPEG。
- 显示原始大小、结果大小和压缩比例。
- 目标大小校验与后端一致。

### 4.2 图片格式转换

- 使用 API v1。
- 支持单文件直接下载、多文件 ZIP。
- 显示文件数、总大小和目标格式。
- 遇到其中一个无效文件时整个任务失败，不返回混合的半成功结果。

### 4.3 文件名提取

- 完全移到浏览器本地。
- 支持目录选择和多文件选择。
- 支持扩展名、相对路径和子目录过滤选项。
- 使用 `Blob` 生成并下载 TXT，不访问服务端 API。

验收：

- 浏览器网络面板确认文件名工具无 API 请求。
- 图片压缩和转换结果内容与扩展名一致。
- 多文件 ZIP 内没有内部任务 ID 和服务器目录结构。
- 三个工具的重置操作都会释放前端对象 URL 和状态。

建议提交：

```text

```

## 4. 测试计划

### 4.1 单元测试

- 文件名和扩展名清理。
- 图片模式与透明通道转换。
- 像素、数量、大小和质量参数边界。
- 任务 ID 和 artifact 路径解析。
- TTL 过期判断。

### 4.2 API 集成测试

- 正常压缩、单图转换和多图 ZIP。
- 错误 MIME、伪装扩展名、损坏图片。
- 大图、超数量、超请求大小。
- 下载存在、不存在和已过期。
- 不接受 JSON 服务器路径参数。

### 4.3 前端行为测试

- 工具切换与状态清理。
- 拖放、文件选择和重复选择。
- 本地文件名导出。
- API 错误映射为用户可理解消息。
- 特殊文件名安全渲染。

### 4.4 容器验收

- `docker compose config`
- `docker compose build`
- 容器健康检查。
- 真实文件通过 Caddy 域名上传和下载。
- 过期清理回收数据卷空间。

## 5. 发布与回滚

### 发布前

1. 分支测试和容器验证全部通过。
2. 审查产品文案、文件限制和隐私说明。
3. 合并到 `main` 并推送。
4. 服务器快进拉取。
5. 重建 Toolmist Compose 项目。

### 发布后

1. 检查 `/healthz`。
2. 检查首页、三种工具和 HTTPS 下载。
3. 检查容器日志和数据卷增长。
4. 观察 CPU、内存和失败率。

### 回滚

保留发布前提交 SHA。应用和静态页面均在同一镜像中，出现问题时将服务器仓库切回已知提交并重建 `toolmist`，Caddy 上游无需修改。

临时结果不纳入回滚保证，回滚时可以清理 Toolmist 自己的数据卷，但不能操作其他 Compose 项目或卷。

## 6. 首轮执行顺序

文档确认后按以下顺序开始编码：

1. Phase 1：应用骨架。
2. Phase 2 的 artifact storage、统一错误和限制基础。
3. Phase 3：页面静态骨架与视觉系统。
4. Phase 4：逐个接入三个工具。
5. 完成 Phase 2 清理机制和 Phase 5 加固。

不先做视觉页面再补后端边界，也不在首轮加入 Silk 转换、数据库或任务队列。

## 7. 文档确认点

进入 Phase 1 前确认以下默认决策：

- Toolmist 作为公开、无需登录的工具站。
- 首期三个工具为压缩、格式转换、文件名提取。
- 文件名提取完全在浏览器运行。
- 结果默认保留 1 小时。
- 图片拼接作为首期之后的第一个候选工具。
- Silk 转 MP3 暂不进入公网版本。
