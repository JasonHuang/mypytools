# Toolmist 产品定义

## 1. 产品定位

Toolmist 是一个公开、轻量、无需注册的日常在线工具站。

它不追求收录尽可能多的工具，而是沉淀维护者自己高频使用、适合浏览器快速完成、能够明确控制资源消耗的工具。用户应当可以在进入页面后立即理解用途，上传或选择本地文件，完成处理并下载结果，然后离开。

产品主张：

> 常用工具，即开即用；文件短暂处理，不做长期保存。

## 2. 目标用户

- 需要偶尔处理图片或文件、但不想安装桌面软件的普通用户。
- 在手机、平板或临时电脑上需要快速完成一次处理的用户。
- 维护者本人及其日常协作对象。

首期不面向需要批量自动化、开放 API 集成或长期任务管理的专业工作流。

## 3. 产品原则

### 3.1 即开即用

- 无注册、无登录、无用户中心。
- 首页直接展示工具，不设置营销落地页。
- 每个工具在一个清晰的工作区内完成输入、配置、处理和下载。

### 3.2 少而可靠

- 只上线真实高频、能长期维护的工具。
- 每个工具必须有清晰的输入限制、错误提示和自动化测试。
- 不展示尚未实现、只有按钮没有实际处理逻辑的功能。

### 3.3 隐私优先

- 浏览器能够本地完成的工作优先在浏览器完成。
- 必须上传的文件只用于当前处理任务。
- 页面明确展示文件大小限制和临时文件保留策略。
- 不建立用户文件库，不把上传文件用于分析或训练。

### 3.4 公开但有边界

- 匿名访问不等于无限资源。
- 服务端限制请求大小、文件数量、图片像素、并发数和处理时长。
- 对异常请求返回稳定的错误码，不在前端暴露服务器路径和堆栈。

### 3.5 移动端可用

- 核心工具必须能够在手机浏览器完成操作。
- 控件使用足够大的点击区域，结果下载入口始终明确可见。
- 页面不依赖悬停操作或桌面端文件路径概念。

## 4. 信息架构

### 4.1 首页

首页由四部分组成：

1. 顶部品牌区：Toolmist、简短定位、服务状态入口。
2. 工具导航区：按类别展示可用工具，首期只有“图片与文件”。
3. 当前工具工作区：工具介绍、输入区、参数区、执行状态、结果区。
4. 页脚：隐私说明、文件保留时间、版本与健康状态链接。

首期不加入博客、账号、收藏、历史记录和评论系统。

### 4.2 工具卡片

每个工具卡片至少包含：

- 工具名称和一句话用途。
- 输入格式与大小限制。
- “本地处理”或“临时上传”标识。
- 打开工具的明确操作。

### 4.3 工具工作区

所有工具遵循统一流程：

1. 选择或拖入文件。
2. 展示已选择文件、总大小和约束。
3. 调整少量必要参数。
4. 开始处理并显示当前状态。
5. 展示结果摘要与下载按钮。
6. 允许清空当前任务并重新开始。

页面不再展示全局“实时日志”。面向公众的状态只包含可理解的处理阶段和错误信息，详细日志只保留在服务端。

## 5. 工具范围

### 5.1 首期工具

#### 图片压缩

- 输入：JPG、PNG、WebP、HEIC/HEIF。
- 输出：JPEG。
- 参数：目标大小。
- 处理方式：上传到服务端，结果临时保存并下载。

#### 图片格式转换

- 输入：JPG、PNG、WebP、BMP、TIFF、HEIC/HEIF。
- 输出：JPG、PNG、WebP。
- 支持多文件，多个结果打包为 ZIP。
- 处理方式：上传到服务端。

#### 文件名提取

- 输入：浏览器选择的本地文件或目录。
- 输出：TXT。
- 参数：是否保留扩展名、是否包含子目录路径。
- 处理方式：完全在浏览器本地完成，不上传文件和文件名列表。

### 5.2 下一阶段候选

#### 图片拼接

- 输入多张图片。
- 支持横向、纵向、间距、背景色和输出质量。
- 复用现有 `stitch_images.py` 的核心算法，但先补足像素限制和测试。

### 5.3 暂缓上线

#### Silk 转 MP3

暂不进入公开站首期，原因：

- 依赖 FFmpeg 和额外 Silk 解码器，增加镜像与供应链复杂度。
- 音频任务比当前图片任务更容易形成高 CPU 占用。
- 需要先确认支持的 Silk 变体、文件识别方式和公开服务的版权/滥用边界。

CLI 脚本可以继续保留，待完成独立技术评估后再决定是否产品化。

## 6. 公开页面文案基线

### 品牌

- 名称：Toolmist
- 中文定位：轻量、即用即走的在线工具箱
- 英文辅助语：Small tools for everyday tasks

### 隐私提示

> 文件仅用于当前处理任务，处理结果会在短时间后自动删除。文件名提取工具完全在浏览器本地运行。

### 空状态

> 选择一个工具开始。无需注册，也不会保留你的处理历史。

## 7. 成功标准

首期重构完成需要满足：

- 首页在桌面端和移动端均能清晰选择并使用三个首期工具。
- 页面不再出现本机路径、服务器路径或全局后台日志概念。
- 文件名提取不产生网络请求。
- 服务端工具使用一致的 API 响应和下载模型。
- 上传、格式、文件数量、像素、超时等限制在前后端均有提示和校验。
- 处理结果可下载，过期后不可访问，并有自动清理机制。
- Docker、健康检查和现有 `toolmist.com` 部署方式保持兼容。
- 核心行为有自动化测试覆盖。

## 8. 非目标

首期明确不做：

- 用户账号、云同步和处理历史。
- 用户上传内容的永久存储。
- 对外承诺稳定的第三方 API。
- 广告、付费、订阅或配额购买。
- 大规模视频、音频或文档转换。
- 在应用代码内实现完整 DDoS 防护。
